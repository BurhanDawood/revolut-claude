## Summary

A comprehensive security audit of `server.js` was conducted across all HTTP endpoints, hostile input variants, secret handling, Telegram callbacks, and money-moving pathways. A critical authentication bypass was identified where double-slash URLs (e.g. `POST //api/revolut/trade`) bypass the `#349` gate while reaching route handlers in Express. Secondary findings include an unauthenticated Telegram setup endpoint, GET endpoints with side effects accessible via `DASHBOARD_TOKEN`, and non-constant-time secret comparisons.

---

## Findings

1. **HIGH**: Double-slash URL paths (`//api/*`) bypass the `#349` auth gate entirely while reaching Express handlers.
   - **Evidence** (`server.js` line 1832):
     ```js
     const p = req.path.toLowerCase();
     if (!(p.startsWith('/api/') || p.startsWith('/portfolio/'))) return next();
     ```
   - **Why it matters**: If a request uses a double leading slash (such as `POST //api/revolut/trade` or `POST //api/capital`), `req.path` in Express evaluates to `//api/revolut/trade`. `p.startsWith('/api/')` returns `false`, causing the gate middleware to call `next()`. Express's router normalizes slashes during route matching and executes `app.post('/api/revolut/trade')` or `app.post('/api/capital')` with zero authentication. Any unauthenticated attacker on the internet can execute trades, alter capital, or rewrite database records.

2. **MEDIUM**: `/telegram-setup` is an unauthenticated public GET route.
   - **Evidence** (`server.js` line 2761):
     ```js
     app.get('/telegram-setup', async (req, res) => {
       const token = process.env.TELEGRAM_BOT_TOKEN;
     ```
   - **Why it matters**: The endpoint sits outside the `#349` gate and performs no header or token authentication. Anyone on the web can invoke `GET /telegram-setup`, triggering outbound HTTP calls to Telegram's `setWebhook` API. While the target URL is hardcoded, unauthenticated access permits external manipulation of bot webhook registration state.

3. **MEDIUM**: `GET /api/test/macro-news` has state-mutating side effects accessible with read-only `DASHBOARD_TOKEN`.
   - **Evidence** (`server.js` line 2746):
     ```js
     app.get('/api/test/macro-news', async (req, res) => {
       lastMacroNewsCallTime = 0;
     ```
   - **Why it matters**: Decision D18 and ticket `#349` permit all GET requests for callers with `DASHBOARD_TOKEN`. However, `GET /api/test/macro-news` resets rate limits, executes paid Anthropic Claude API calls, and sends Telegram alerts. A dashboard token holder can drain API credits and flood Telegram alerts via this GET endpoint.

4. **LOW**: Secret header comparisons use non-constant-time equality (`===` / `!==`).
   - **Evidence** (`server.js` line 1836):
     ```js
     const matches = (v) => typeof v === 'string' && v.length >= 24 && sent === v;
     ```
   - **Why it matters**: Standard JavaScript string equality checks (`===` and `!==`) terminate on the first mismatched byte, introducing a timing side-channel. `crypto.timingSafeEqual` should be used for secret comparisons (`API_TOKEN`, `DASHBOARD_TOKEN`, `DEV_LOG_TOKEN`, `BRIDGE_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`).

5. **LOW**: Exact string matching on `DASHBOARD_WRITES` rejects trailing slashes (`/api/pause/`).
   - **Evidence** (`server.js` line 1830):
     ```js
     const DASHBOARD_WRITES = ['/api/pause', '/api/resume', '/api/sweep/config'];
     ```
   - **Why it matters**: Callers using `DASHBOARD_TOKEN` with a trailing slash (e.g. `POST /api/pause/`) will have `DASHBOARD_WRITES.includes('/api/pause/')` evaluate to `false`, blocking legitimate dashboard writes.

## Recommendations for Claude

1. **Fix Double-Slash Bypass in `#349` Auth Gate**:
   - **What**: Sanitize `req.path` by stripping multiple leading slashes (e.g. `req.path.replace(/^\/+/, '/')`) before checking `p.startsWith('/api/')` or `p.startsWith('/portfolio/')`.
   - **Why**: Currently, a request path like `//api/revolut/trade` causes `p.startsWith('/api/')` to evaluate to `false`, allowing the request to bypass the gate and reach the Express route handler unauthenticated.

2. **Protect `/telegram-setup` Route**:
   - **What**: Require `API_TOKEN` or `DEV_LOG_TOKEN` header on `/telegram-setup` or move it under `/api/`.
   - **Why**: `/telegram-setup` is currently an unauthenticated GET route open to any external caller, allowing arbitrary third parties to trigger Telegram webhook setup calls.

3. **Protect `GET /api/test/macro-news` with `API_TOKEN`**:
   - **What**: Change `GET /api/test/macro-news` to require `API_TOKEN` or convert it to a `POST` route.
   - **Why**: `DASHBOARD_TOKEN` permits all GET routes under `/api/`. `GET /api/test/macro-news` triggers Anthropic API calls and sends Telegram messages, allowing a read-only token holder to consume API budget.

4. **Use Constant-Time Secret Comparisons**:
   - **What**: Use `crypto.timingSafeEqual` (with string length padding) for secret comparisons (`API_TOKEN`, `DASHBOARD_TOKEN`, `DEV_LOG_TOKEN`, `BRIDGE_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`).
   - **Why**: Standard string equality (`===` / `!==`) exits early on byte mismatches, introducing timing side-channels.

5. **Normalize Trailing Slashes on Gate Exemptions & DASHBOARD_WRITES**:
   - **What**: Normalize trailing slashes on `p` (e.g. `p.replace(/\/+$/, '')`) prior to checking `DASHBOARD_WRITES`, `/api/health`, and `/api/bridge`.
   - **Why**: `/api/pause/` fails to match `DASHBOARD_WRITES`, blocking legitimate dashboard operations, while `/api/health/` gets trapped in the gate instead of passing through as exempt.
