## Summary

This design specification defines a bi-directional, state-persistent laddered pump-loop engine for Dev-348. It extends the existing pump-arm, trailing-stop, and trough-tracking routines in `server.js` to execute iterative 50% sell legs on trailing stops when price pumps, while tracking trough-bounces on retraces to execute tiered buybacks using ring-fenced proceeds. All state transitions, invariants, hostile races, test vectors, and integration points are specified below for Claude to implement upon Bryan's approval.

## Findings

1. **HIGH: Persistence Gap in `pump_armed_rules` for Multi-Leg State**
   * **Evidence:** In `server.js` (lines 580–600), `pump_armed_rules` only persists single-cycle fields (`sale_price`, `reference_base`, `retrace_gate`, `trough_low`, `trough_armed`, `sale_proceeds_usd`).
   * **Why it matters:** If the process restarts mid-cycle (e.g. after Leg 1 Sell or Buy Tier 1), in-memory state in `troughTrackers` is lost or desynchronized from the single-value DB columns, risking double-sells, lost ring-fenced proceeds, or incorrect buyback sizing on recovery.

2. **MEDIUM: Live Shadow Runner Omits Re-arm and Ladder Configuration**
   * **Evidence:** In `server.js` within `runFastScan()`:
     ```javascript
     const shCfg = { arm_pump_pct: parseFloat(r.arm_pump_pct), arm_window_min: parseInt(r.arm_window_min) || 60,
       sell_tiers: sTiers, buy_tiers: bTiers,
       tier_cooldown_min: r.tier_cooldown_min != null ? Number(r.tier_cooldown_min) : 15,
       min_tier_usd: r.min_tier_usd != null ? parseFloat(r.min_tier_usd) : 2,
       entry_floor: r.entry_floor != null ? parseFloat(r.entry_floor) : null };
     ```
   * **Why it matters:** `shCfg` does not pass `rule_mode`, `rearm_from`, or `max_legs` to `shadowEvalTier()`. Consequently, live shadow evaluation never tests re-arm or multi-leg laddering, preventing live shadow validation before real money deployment.

3. **MEDIUM: Absence of Single-Engine Mutex Between Standalone and Loop Trough Trackers**
   * **Evidence:** `server.js` manages `troughTrackers` and `standaloneTroughTrackers` in two separate Maps and distinct execution blocks inside `runFastScan()`.
   * **Why it matters:** If a coin is registered in both `pump_armed_rules` and `standalone_trough_trackers`, both trackers can trigger buy orders on the same 30s tick, causing race conditions, over-allocation of USD, or order rejection due to insufficient funds.

4. **LOW: Dust Accumulation via Iterative 50% Sells**
   * **Evidence:** In `server.js` (`autoExecuteSell()`):
     ```javascript
     const sellQty = currentQty * (maxPct / 100);
     if (sellQty <= 0 || !isFinite(sellQty) || valueUSD < 1) { ... return { executed: false, reason: 'dust' }; }
     ```
   * **Why it matters:** Repeated 50% legs (e.g. $100 -> $50 -> $25 -> $12.5 -> $6.25 -> $3.12 -> $1.56 -> $0.78) quickly hit the $1 USD venue minimum, leaving un-sellable dust that halts ladder progression unless handled explicitly.

#### 2. Core Engine Invariants

1. **Hard Entry Floor Guard (D3):**
   No auto-sell leg may execute if `current_price <= entry_floor`. The effective entry floor is: `sell_floors[coin]` > `pump_armed_rules.entry_floor` > `entry_prices.entry_price`. If all three are missing/null, the auto-sell MUST fail safe and block execution.

2. **Isolated Ring-Fenced Capital:**
   Buyback tiers MUST NOT spend more USD than is recorded in `pump_armed_rules.ringfenced_usd`. If live available USD on the venue is less than the intended tier size, the engine buys only up to `available_usd` or skips if below `min_tier_usd`. Proceeds from manual sells by Bryan are NEVER added to `ringfenced_usd`.

3. **Maximum Sell Legs Cap:**
   The total number of sell legs within a single pump move MUST NOT exceed `max_legs` (default 3). Once `legs_sold == max_legs`, the re-arm UP transition is disabled for the remainder of that cycle.

4. **Single Engine / Single Mutex Per Symbol:**
   A coin CANNOT be active in multiple execution engines simultaneously. If `pump_armed_rules` is active (`loop_enabled = 1`), `standalone_trough_trackers` for that symbol MUST be disabled/rejected.

5. **Buyback Ceiling Guard:**
   The engine MUST NOT execute a trough buyback if `current_price > sale_price * (1 + buyback_ceiling_pct/100)`. If price rises above this ceiling before a trough bounce completes, the buyback is abandoned and ringfenced USD is released.

6. **Monotonic Trough Low Tracking:**
   During `TROUGH_TRACKING`, `trough_low` decreases strictly when lower prices are observed. `bounce_pct` is measured strictly from `trough_low`.

7. **Crash-Safe Ordering (D14):**
   Before placing any market order to the venue, in-memory Map state must be updated or cleared synchronously so concurrent intervals/ticks cannot double-fire.

8. **Reserved Balance Ownership (D15):**
   Holding calculations must use `available + reserved` to determine total coin position. A resting limit order or card pre-authorization does not reduce ownership.

#### 4. Hostile Cases & Required Engine Behaviour

1. **Server Restart Mid-Cycle:**
   * *Requirement:* All state machine variables (`cycle_state`, `legs_sold`, `ringfenced_usd`, `rearm_target`, `retrace_gate`, `trough_low`, `buy_tier_1_fill_price`) MUST be persisted in DB columns on `pump_armed_rules`. On startup, `runFastScan` rebuilds the in-memory Maps directly from the DB.

2. **Bryan Trades Symbol Manually Mid-Cycle:**
   * *Requirement:* Before each sell leg, the engine re-reads total position (`available + reserved`). `sell_pct` applies to the live position at execution time. Proceeds from manual trades are ignored.

3. **Order Placement Fails or Partially Fills:**
   * *Requirement:* On market order failure, the engine remains in its current state, retries on the next tick (subject to `tier_cooldown_min`), and alerts Telegram. On partial fill, `ringfenced_usd` is credited ONLY with actual net filled USD (`filled_qty * avg_fill_price - fees`).

4. **Fast Price Gap Across Multiple Triggers in One 30s Tick:**
   * *Requirement:* If a single tick gaps through trailing stop AND retrace gate, the engine executes the sell leg first. The trough gate is evaluated on the SUBSEQUENT tick using the new fill price as baseline.

5. **Simultaneous Re-arm and Trough Triggers in Same Tick:**
   * *Requirement:* Priority is given to **Re-arm UP** if `tick.high >= rearm_target`. If price is falling (`tick.low <= retrace_gate`), trough tracking arms.

6. **Kraken vs Revolut Execution Routing:**
   * *Requirement:* The engine checks `KRAKEN_MONITORED_COINS`. If true, order calls route to `executeKrakenTrade()` / `autoExecuteKrakenSell()`; otherwise `placeRevolutOrder()` / `autoExecuteSell()`.

7. **Auto-Exec Master Switch Flipped Off Mid-Cycle:**
   * *Requirement:* Invariants D1 and D11 apply. If `ai_auto_execute.enabled` is set to `false` mid-cycle, fast-scan STOPS executing trades automatically, emits Telegram notifications on triggers, and leaves the cycle state intact in DB for manual resume or resolution.

8. **Dust Position Residuals:**
   * *Requirement:* If position USD value falls below `min_tier_usd` ($2.00) or venue minimums, the engine halts further sell legs, notifies Telegram, and transitions to buyback watch or IDLE.

9. **Stale Armed Loop on Exited Coin:**
   * *Requirement:* On every fast-scan tick, if position quantity is 0 and `ringfenced_usd == 0`, the engine self-heals by resetting `armed = 0`, `loop_enabled = 0`, clearing runtime state, and logging to Telegram.
