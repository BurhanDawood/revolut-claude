## Summary

Audit of `public/dashboard.html` and `public/dashboard.js` against `server.js` identified five broken endpoints (`/api/trade/execute`, `/api/rebalancing`, `/api/rebalancing/analyse`, `/api/journal`, and `/api/profile/preference`). Under Decision D18 and ticket #349 key rules, dashboard trade execution must be removed, broken read routes re-pointed to existing endpoints, and safe read-only analysis POST routes added to `DASHBOARD_WRITES`.

## Findings

1. **Broken Trade Execution Control (`POST /api/trade/execute`)**
   - **Severity:** HIGH
   - **Evidence:** `public/dashboard.js`, function `submitKrakenTrade`:
     > `fetch('/api/trade/execute', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body) })`
   - **Why it matters:** In `server.js`, no route `/api/trade/execute` exists (Kraken trade execution uses `POST /api/kraken/trade`). Furthermore, under Decision D18 and ticket #349 security rules, the `DASHBOARD_TOKEN` must NEVER be permitted to execute trades or move money. Attempting trades from the dashboard fails with 404/401 and violates security policy.

2. **Broken Rebalancing Tab Data Fetch (`GET /api/rebalancing`)**
   - **Severity:** HIGH
   - **Evidence:** `public/dashboard.js`, function `loadRebalancing`:
     > `fetchData('/api/rebalancing').then(function(data) {`
   - **Why it matters:** In `server.js`, no route `GET /api/rebalancing` exists. Server exposes `GET /api/rebalancing/positions` and `GET /api/rebalancing/latest`. `fetchData` catches the 404 error, logs it, and returns `null`. `loadRebalancing()` exits at `if (!data) return;`, leaving the entire Rebalancing tab (health donut, positions table, freed capital calculator) permanently frozen on "Loading…".

3. **Broken Rebalancing Analysis Trigger (`POST /api/rebalancing/analyse`)**
   - **Severity:** HIGH
   - **Evidence:** `public/dashboard.js`, function `runRebalancingAnalysis`:
     > `fetch('/api/rebalancing/analyse', { method: 'POST' })`
   - **Why it matters:** In `server.js`, the route is `app.post('/api/rebalancing', ...)`. Moreover, `POST /api/rebalancing` is not in `DASHBOARD_WRITES` (`server.js`, `const DASHBOARD_WRITES = ['/api/pause', '/api/resume', '/api/sweep/config']`). Tapping "Refresh Analysis" fails with 404 and 401 Unauthorized.

4. **Broken Journal Trade Logging Form (`POST /api/journal`)**
   - **Severity:** MEDIUM
   - **Evidence:** `public/dashboard.js`, function `submitJournalEntry`:
     > `fetch('/api/journal', { method: 'POST', headers: { 'Content-Type': 'application/json' },`
   - **Why it matters:** In `server.js`, the route is `app.post('/api/journal/entry', ...)`. Furthermore, write routes under `/api/journal` require `API_TOKEN` (which stays unset). Submitting manual trade logs via the dashboard fails with 404 and 401.

5. **Broken Profile Preference Submission (`POST /api/profile/preference`)**
   - **Severity:** MEDIUM
   - **Evidence:** `public/dashboard.js`, function `addPreference`:
     > `fetch('/api/profile/preference', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ preference: val }) })`
   - **Why it matters:** In `server.js`, the route is `app.post('/api/profile', ...)`, which expects `{ key, value }`. Also, `POST /api/profile` is not in `DASHBOARD_WRITES`. Adding a preference from the dashboard fails with 404 and 401.

6. **Silent Error Handling in `fetchData` Masks Endpoint Failures**
   - **Severity:** MEDIUM
   - **Evidence:** `public/dashboard.js`, function `fetchData`:
     > `.catch(function(e) { console.error('Fetch error ' + url + ':', e.message); return null; })`
   - **Why it matters:** When endpoints fail (404, 401, 500), `fetchData` silently suppresses errors and returns `null`. UI elements remain frozen indefinitely on "Loading…" without notifying the user or requesting re-authentication.

7. **Misleading Realised P&L Figures in Activity Feed & Journal Stats**
   - **Severity:** MEDIUM
   - **Evidence:** `server.js`, function `autoLogTrade` inserts into `trading_journal` using `price` (the ticker price at scan time) rather than actual venue fill price. See tickets #338, #340, and #347.
   - **Why it matters:** P&L figures computed directly from `trading_journal` represent requested/scanned prices rather than confirmed venue fill prices, causing minor drift vs real exchange history.

8. **Dead "Edit" Instruction and CSS in Activity Feed**
   - **Severity:** LOW
   - **Evidence:** `public/dashboard.html` states:
     > `All trades, payments, sweeps and transfers. Tap Edit on any entry to correct the reason or type.`
     However, `public/dashboard.js` function `loadActivity()` does not render any edit buttons or forms.
   - **Why it matters:** Promises an "Edit" feature in the UI description that JavaScript does not render. (`PATCH /api/activity/:id` exists in `server.js` but requires `API_TOKEN`).

9. **Direct `/dashboard.html` Access Bypasses Injection of Auth Helper**
   - **Severity:** LOW
   - **Evidence:** `server.js`, route `app.get('/', ...)` injects `<script src="/dashboard-auth.js"></script>` into `dashboard.html`. Direct request to `/dashboard.html` served via `express.static` does not inject the script.
   - **Why it matters:** Navigating directly to `http://<host>/dashboard.html` bypasses key injection, causing all API calls to fail with 401 Unauthorized.

## Recommendations for Claude

1. **Remove Trade Execution UI from Dashboard (Decision D18 Compliance)**:
   - In `public/dashboard.html`, remove the "⚡ Execute Trade" card (`<div class="card">` containing `k-symbol`, `k-side`, `k-volume`, `k-ordertype`, `k-price`, and `submitKrakenTrade()`).
   - In `public/dashboard.js`, remove function `submitKrakenTrade()`.
   - *Why:* Standing Decision D18 and ticket #343 brief state that the dashboard key must NEVER place trades or move money. Trade approvals belong exclusively in Telegram.

2. **Fix Rebalancing Tab Data Loading (`public/dashboard.js`)**:
   - In `public/dashboard.js`, update `loadRebalancing()` to fetch `GET /api/rebalancing/positions` and `GET /api/rebalancing/latest` concurrently using `Promise.all`.
   - Map `positions` data to `rb-total-value`, `rb-total-loss`, `rb-recovery-pct`, health legend counts, and `rb-positions-body`. Map `latest.analysis` to `rb-analysis-text` and `latest.created_at` to `rb-analysis-date`.
   - *Why:* Replaces 404 `/api/rebalancing` call with existing valid read routes.

3. **Fix Rebalancing Analysis Trigger (`public/dashboard.js` and `server.js`)**:
   - In `public/dashboard.js`, update `runRebalancingAnalysis()` to send `POST /api/rebalancing`.
   - In `server.js`, add `'/api/rebalancing'` to `DASHBOARD_WRITES` array.
   - *Why:* `/api/rebalancing` generates AI analysis advice and does not execute trades or alter capital. Adding it to `DASHBOARD_WRITES` allows dashboard users to trigger analysis safely.

4. **Remove or Fix Manual Journal & Preference Logging**:
   - In `public/dashboard.html` and `public/dashboard.js`: Remove the "Log a Trade" form and "Add Preference" form from the Journal tab.
   - *Why:* Trade logging and preference management are handled via Telegram and MCP tools. Removing non-functional write controls simplifies the dashboard to its core read-only purpose.

5. **Fix Activity Feed Description**:
   - In `public/dashboard.html`, remove "Tap Edit on any entry to correct the reason or type" from the Activity tab header text.
   - *Why:* Eliminates dead UI instructions for unrendered edit buttons.

6. **Redirect `/dashboard.html` to `/`**:
   - In `server.js`, add a route `app.get('/dashboard.html', (req, res) => res.redirect('/'));`
   - *Why:* Ensures direct bookmarks to `/dashboard.html` receive the injected `dashboard-auth.js` helper script.

7. **Improve `fetchData` Error Reporting**:
   - In `public/dashboard.js`, update `fetchData()` to display a toast notification on HTTP 401 or 404 errors rather than returning `null` silently.
   - *Why:* Prevents frozen UI elements and informs the user if authorization expires.
